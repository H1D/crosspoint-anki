crosspoint-anki flasher

crosspoint-anki is a fork of CrossPoint Reader that adds Anki flashcard review and "add word from the dictionary" on the device. This page writes a release build into the inactive OTA slot of your reader over USB, the same way the official CrossPoint flasher does.

This flasher needs WebSerial, which is only available in desktop Chrome or Edge (not Firefox or Safari, not mobile browsers).

1. Device

Sticky and PaperMono: this page only updates a device that already runs CrossPoint. A first install from the stock firmware needs the bootloader and partition table replaced too; do that once with the official flasher, then come back here.

2. Firmware

Flash a local .bin instead

Pick a crosspoint-<version>-<device>.bin downloaded from the releases page, or your own build (.pio/build/<env>/firmware.bin). The file is checked for the ESP image format and chip before anything is written.

3. Flash

  1. Wake or unlock the reader and connect it to this computer with a USB-C data cable.
  2. No button combination is needed: the flasher puts the chip into download mode over USB. Do not press Reset while flashing.
  3. Click the button below and pick the device in the browser's serial port dialog (it appears as a USB JTAG/serial or CrossPoint port).
    
    
    

    
    
      
    If the device does not show up
    
      
      
        
    • Try another USB port or cable (some cables are charge-only).
      • 
        
    • Close other programs that may hold the serial port (PlatformIO monitor, Arduino IDE).
      • 
        
    • Some Xteink X3/X4 units bought from third-party stores ship with USB flashing locked.
          Those need the Xteink Unlocker once;
          units bought from xteink.com are not locked.
      • 
        
    • On Linux, your user needs access to the port (usually the dialout or
          uucp group).
      • 
      
    
      
    What this does
    
      
    
        The flasher reads the partition table at 0x8000, reads otadata to find the
        running OTA slot, writes the firmware into the other slot (app0 or app1)
        and then writes a new otadata entry so the bootloader boots it. The bootloader,
        partition table, NVS settings and the previously running firmware stay in place. This is what
        the device's own Wi-Fi OTA update does, over USB instead.
      
    
      
    
        Command-line alternative: esptool.py --chip esp32c3 write_flash 0x10000 firmware.bin
        (X3/X4; esp32s3 for the others) writes app0 directly, as in the
        README.
